# «Второй мозг»: архитектура, стек и лучшие практики

> Статус: **предложение (v0.1)** — к обсуждению перед реализацией MVP.

## 1. Главная идея в одном абзаце

Мы **не пишем свой ChatGPT**. Чат, голос, память и мобильные приложения уже есть
в Claude (web, Desktop, iOS, Android) и работают **по подписке Pro/Max**.
Мы строим **«мозг» на своём сервере** — хранилище всех файлов и заметок с
умным поиском — и подключаем его к Claude как **custom connector (удалённый MCP‑сервер)**.
В итоге вы общаетесь с привычным красивым чатом Claude на компе и телефоне
(в т.ч. голосом), а Claude сам лезет в ваш «мозг», находит нужное, цитирует
источник и сохраняет новое.

```
 ┌──────────── ВВОД (захват) ────────────┐        ┌────────── ВЫВОД (общение) ──────────┐
 │ Telegram‑бот: файлы, фото, голосовые, │        │ Claude app: web / Desktop / iOS /    │
 │ ссылки, пересылка сообщений           │        │ Android, голосовой режим, Projects,  │
 │ Веб‑страница / PWA «Поделиться»       │        │ встроенная память                    │
 │ E‑mail ящик brain@…                   │        │            ▲                         │
 │ Папка на компе (Syncthing)            │        │            │ MCP (custom connector,  │
 │ Сам Claude: «запомни это»             │        │            │ OAuth, HTTPS)           │
 └───────────────┬───────────────────────┘        └────────────┼─────────────────────────┘
                 ▼                                             │
 ┌────────────────────────────── ВАШ СЕРВЕР (Docker Compose) ──┴─────────────────────────┐
 │  Caddy (HTTPS) ─► API + MCP‑сервер (Python, FastAPI + FastMCP)                         │
 │                       │                                                               │
 │  Очередь ─► Воркер обработки:                                                         │
 │     • парсинг (Docling: PDF/DOCX/PPTX/XLSX/HTML, OCR сканов и фото)                   │
 │     • расшифровка аудио/видео (faster‑whisper)                                        │
 │     • чанкинг по структуре + метаданные                                               │

 │  /data/raw — оригиналы файлов   /data/vault — Markdown‑заметки (Obsidian, Git)        │
 │  Куратор: Claude Code (headless, по подписке) по расписанию — разбор Inbox,           │
 │           теги, связи, еженедельный дайджест → Telegram                               │
 │  Бэкапы: restic → внешнее S3‑хранилище (шифрованно)                                   │
```

## 2. Почему именно так (и про «нашу подписку»)

| Требование | Решение |
|---|---|
| Работает по подписке, без оплаты за токены | Подписку Pro/Max по правилам Anthropic можно использовать только в **родных приложениях** (claude.ai, Desktop, Mobile, Claude Code). Сторонние чат‑интерфейсы (Open WebUI, LibreChat и т.п.) и Agent SDK требуют **API‑ключ с оплатой за токены**. Поэтому «мозг» подключается к самому Claude через MCP, а не наоборот. |
| Красиво, «как ChatGPT» | Интерфейс = приложение Claude. Это и есть топовый чат‑UI: история, Projects, артефакты, файлы. |
| Комп + телефон | Custom connectors работают в web, Desktop и мобильных приложениях (добавляются один раз на claude.ai, дальше доступны везде). |
| Голос | Голосовой режим в мобильном приложении Claude + голосовые заметки в Telegram‑бота (расшифровываем на сервере). |
| «Помнил всё» | Три слоя памяти (см. §5): встроенная память Claude + профиль‑«досье» в мозге + вся база знаний с поиском. |
| Быстро находить релевантное | Гибридный поиск (смысловой + по словам) + реранкер + фильтры по метаданным (см. §4). |
| Отделять «мух от котлет» | Строгая структура: Inbox → PARA‑области + типы + сущности (люди, проекты, компании) (см. §3). |
| Приватность | Всё хранится на вашем сервере. В Claude уходят только найденные фрагменты в момент вопроса. |

> **Про «JEV».** Я трактую это как **RAG / векторный поиск** (поиск по смыслу,
> который подтягивает релевантные куски в ответ) — он заложен в ядро архитектуры.
> Если вы имели в виду конкретный продукт/сервис — напишите, встроим.

## 3. Структура знаний: как «отделять мух от котлет»

Лучшая практика — **разделять по назначению, а не по формату файла**, и делать
это автоматически, чтобы вы ничего не сортировали руками.

### 3.1 Поток
1. **Inbox** — всё входящее падает сюда без вопросов (нулевое трение при захвате).
2. **Обработка** (автоматически): извлечь текст → понять тип → предложить область,
   теги, связанных людей/проекты → краткое резюме.
3. **Раскладка** по PARA:
   - **Projects** — то, что имеет цель и срок (ремонт, запуск продукта, переезд);
   - **Areas** — постоянные зоны ответственности (здоровье, финансы, семья, работа);
   - **Resources** — справочное, интересное (статьи, курсы, рецепты);
   - **Archive** — завершённое и неактуальное (не удаляем — ищется, но ниже в выдаче).

### 3.2 Метаданные каждого объекта
| Поле | Пример |
|---|---|
| `type` | note, document, meeting, voice, link, contact, task, idea, fact, receipt |
| `area` / `project` | Финансы / «Покупка квартиры» |
| `entities` | люди, компании, места (связи → граф) |
| `date_event` vs `date_added` | когда событие было ≠ когда сохранили |
| `source` | telegram, email, upload, claude, folder |
| `status` | inbox, filed, archived, superseded |
| `confidence` | для автоматически распознанных полей |

### 3.3 Сущности и связи (лёгкий граф знаний)
Отдельные таблицы `entities` (человек/компания/проект) и `mentions`. Это даёт
вопросы вида «всё, что связано с Иваном», «что мы решили по проекту X»,
и красивый граф в Obsidian. Полноценный GraphRAG на старте **не нужен** —
дорог и сложен; добавим, если упрёмся.

### 3.4 Время и актуальность
Факты имеют дату. Новый факт может **заменять** старый (`superseded_by`):
«мой тариф — X» → через полгода «тариф — Y». В поиске свежие и актуальные
факты выше, устаревшие помечены.

## 4. Поиск: как находить релевантное быстро и точно

Лучшие практики RAG на 2025–2026:

1. **Парсинг с сохранением структуры** (Docling): заголовки, таблицы, списки,
   номера страниц — а не «каша из текста».
2. **Чанкинг по структуре**: куски ~300–800 токенов по разделам с небольшим
   перекрытием; к каждому куску добавляется **контекстный заголовок**
   («Документ: Договор аренды 2025 → Раздел 4. Оплата»). Это техника
   *contextual retrieval* — заметно снижает промахи.
3. **Гибридный поиск**: смысловой (BGE‑M3, отлично понимает русский и английский)
   **+** полнотекстовый (Postgres FTS, русская морфология) → объединение (RRF).
   Смысловой находит «по смыслу», полнотекстовый — номера, имена, артикулы.
4. **Реранкер** (bge‑reranker‑v2‑m3): из топ‑50 кандидатов выбирает лучшие 8–10.
5. **Фильтры по метаданным** до поиска: область, тип, период, человек.
6. **Всегда цитаты**: каждый фрагмент возвращается с названием, датой и
   ссылкой на оригинал — Claude отвечает со ссылками, можно открыть файл.
7. **Дедупликация** по хэшу содержимого: один и тот же PDF, присланный трижды,
   хранится один раз.
8. **Набор контрольных вопросов** (20–50 штук) для проверки качества поиска
   после каждого изменения.

Всё это работает **локально на сервере** — модели эмбеддингов и реранкера
бесплатные, без внешних API.

## 5. Память: «помнил всё»

| Слой | Что хранит | Как работает |
|---|---|---|
| **Встроенная память Claude** | стиль общения, общий контекст | Включается в настройках Claude, работает сама. |
| **Профиль / досье** (`profile.md` в мозге) | ключевые факты о вас: семья, работа, цели, предпочтения, текущие проекты | Короткий документ (1–2 стр.). Инструкция проекта: «в начале разговора вызови `get_profile`». Обновляется инструментом `remember`. |
| **База знаний** | все файлы, заметки, переписки, расшифровки | Подтягивается поиском по запросу. |
| **Журнал разговоров** (опционально) | итоги важных бесед | По команде «сохрани итог» Claude пишет резюме в мозг. |

Ключевой принцип: **память ≠ база знаний**. Память — маленькая и всегда в
контексте; база — огромная и достаётся поиском. Смешивать нельзя, иначе
контекст забивается мусором.

## 6. Инструменты MCP‑сервера (что Claude «умеет» с мозгом)

| Инструмент | Назначение |
|---|---|
| `search(query, area?, type?, date_from?, date_to?, entity?)` | гибридный поиск, возвращает фрагменты с источниками |
| `get_document(id, section?)` | открыть документ целиком или раздел |
| `save_note(text, title?, area?, tags?)` | сохранить заметку/мысль из разговора |
| `save_file(url \| attachment)` | сохранить файл/ссылку из чата |
| `remember(fact)` / `get_profile()` | досье: запомнить факт о вас / прочитать |
| `list_inbox()` / `file_item(id, area, tags)` | разбор входящих |
| `recent(days, area?)` | что нового за период |
| `related(id \| entity)` | связанные документы, люди, проекты |
| `timeline(entity \| project)` | хронология событий |

Плюс **MCP‑промпты** (быстрые команды в Claude): «Разбери Inbox»,
«Еженедельный обзор», «Что я знаю про …», «Подготовь к встрече с …».

## 7. Рекомендуемый стек

| Слой | Технология | Почему |
|---|---|---|
| Сервер | VPS в ЕС, 8 vCPU / 16 ГБ RAM / 160+ ГБ диск (Hetzner, Netcup и т.п.) | хватает для локальных эмбеддингов и whisper на CPU; ориентировочно €20–35/мес |
| Оркестрация | Docker Compose | просто поднять, обновить, перенести |
| HTTPS | Caddy | автоматические сертификаты Let's Encrypt |
| Бэкенд + MCP | Python 3.12, FastAPI, **FastMCP** (Streamable HTTP) | официальный стандарт MCP, лучшая экосистема для ML |
| Авторизация | OAuth 2.1 (через Google/GitHub‑вход) для коннектора; whitelist user_id для Telegram | доступ только у вас |
| БД | PostgreSQL 17 + **pgvector** | векторы, полнотекст, метаданные, очередь — в одной базе |
| Очередь задач | Procrastinate (на Postgres) | без отдельного Redis |
| Парсинг | **Docling** (+ OCR), trafilatura для веб‑страниц, yt‑dlp для видео | лучшее качество извлечения структуры |
| Расшифровка речи | **faster‑whisper** (large‑v3‑turbo, int8) | локально, хорошо знает русский |
| Эмбеддинги | **BGE‑M3** через Infinity / TEI | мультиязычная, dense+sparse, бесплатно |
| Реранкер | bge‑reranker‑v2‑m3 | +точность поиска |
| Заметки | Markdown‑хранилище, совместимое с **Obsidian**, версионирование в Git | открытый формат, не зависим от сервиса |
| Захват | Telegram‑бот (aiogram), веб‑загрузка (PWA с «Поделиться»), IMAP‑ящик | удобный ввод с любого устройства |
| Куратор | **Claude Code headless** по cron (`claude -p …`, токен подписки через `claude setup-token`) | авто‑разбор Inbox, связи, дайджесты — по подписке, без API |
| Бэкапы | restic → S3‑совместимое хранилище (Backblaze B2 / Hetzner Storage Box), шифрование | правило 3‑2‑1 |
| Мониторинг | Uptime Kuma + логи | знать, что всё живо |

> **Важно про куратора.** Claude Code по подписке — это «родное» приложение
> Anthropic, его можно запускать на своём сервере для личных задач. Лимиты
> подписки при этом общие с вашим чатом, поэтому задачи куратора делаем
> лёгкими и ночными. Если когда‑нибудь мозгом будет пользоваться кто‑то ещё
> (семья, команда) — для автоматики нужен будет API‑ключ.

## 8. Как этим пользоваться

### С телефона
- **Сохранить**: «Поделиться» → Telegram‑бот (файл, фото, ссылка, пересланное
  сообщение) или надиктовать **голосовое** боту — он расшифрует и разложит.
- **Спросить**: приложение Claude → проект «Второй мозг» → текстом или
  **голосовым режимом**: «Что мне врач говорил про анализы в мае?»
- **Получать**: утренний/недельный дайджест и напоминания приходят в Telegram.

### С компьютера
- **Сохранить**: перетащить файл на веб‑страницу мозга, в Telegram Desktop или
  в синхронизируемую папку `~/Brain/Inbox`.
- **Спросить**: Claude Desktop (быстрый вызов горячей клавишей) или claude.ai.
- **Смотреть «библиотеку»**: Obsidian — граф связей, папки PARA, поиск,
  Canvas‑доски. Это «красивая витрина» всего, что лежит в мозге.

### Настройка Claude (один раз)
1. claude.ai → Settings → Connectors → *Add custom connector* → URL
   `https://brain.<ваш-домен>/mcp` → вход через OAuth.
2. Создать **Project «Второй мозг»** с инструкцией (правила: всегда искать в
   мозге перед ответом, всегда указывать источники, сохранять важное, в начале
   беседы читать профиль).
3. Включить встроенную память Claude.

## 9. Готовые решения — почему не они (как основа)

| Продукт | Плюсы | Почему не основа |
|---|---|---|
| Open WebUI / LibreChat / AnythingLLM | красивый чат, RAG из коробки | нужен **API‑ключ** (оплата за токены), подписка Claude не подходит |
| Khoj | готовый «второй мозг», self‑host | то же — нужен API/своя модель; слабее чат |
| NotebookLM | отличный поиск по источникам | лимиты на источники, данные у Google, нет единой памяти |
| Obsidian + плагины (Smart Connections, Copilot) | отличная витрина | ИИ через API‑ключи, нет удобного захвата с телефона |
| Mem, Notion AI, Reflect | красиво, сразу работает | данные не у вас, отдельная подписка, ограниченный контроль |

Наш вариант берёт лучшее: **UI и голос от Claude по подписке**, **данные и
поиск — свои**, **Obsidian — как витрина**.

## 10. Безопасность и надёжность
- Доступ к MCP только через OAuth, Telegram‑бот отвечает только вашему user_id.
- Диск с данными и бэкапы шифруются; секреты — в `.env`, не в Git.
- Ежедневные инкрементальные бэкапы + ежемесячная проверка восстановления.
- Оригиналы файлов **никогда не удаляются** автоматически — только архивируются.
- Чувствительные области (паспорта, медицина) можно пометить `private`:
  поиск отдаёт только факт наличия документа, а не содержимое, пока вы явно
  не попросите.
- Помните: найденные фрагменты при ответе передаются в Claude (Anthropic).

---

## 11. Ограничения (честно)
- Claude не пишет вам первым — для дайджестов и напоминаний используем Telegram‑бота.
- Работа инструментов в **голосовом режиме** мобильного приложения проверим на
  MVP; если будут ограничения — голосовой ввод в обычном чате работает всегда.
- Лимиты подписки общие для чата, Claude Code и куратора.
- Очень большие файлы (часовые видео) обрабатываются минуты, не мгновенно.

## 13. Что нужно решить перед стартом
1. Какой у вас тариф Claude — Pro или Max? (влияет на нагрузку куратора)
2. Где сервер: арендуем новый VPS или есть свой?
3. Домен: есть ли, или берём новый?
4. Telegram как основной канал захвата — ок?
5. Где сейчас лежат заметки/файлы (Google Drive, Notion, Obsidian, телефон)? — для первичного импорта.
6. Что такое «JEV» в вашем запросе — подтвердите, что это RAG/векторный поиск.
